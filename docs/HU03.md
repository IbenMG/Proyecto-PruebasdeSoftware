# HU-03: crear, editar y publicar campañas

## Alcance

- Desde Main, un usuario autenticado puede entrar a Crear campaña.
- Título, descripción, categoría, meta, fecha e información del creador son obligatorios.
- Se admite una imagen opcional por campaña, reutilizando el campo existente. Puede reemplazarse o quitarse al editar.
- Publicar crea inmediatamente la campaña y abre su detalle público con confirmación. No hay borradores.
- El creador puede editar su campaña. Otros usuarios no pueden modificarla.
- La meta debe ser positiva; la fecha puede ser hoy o posterior. La fecha de referencia usa America/Santiago.
- Mis campañas muestra solo las del usuario conectado, con monto recaudado y meta.
- El monto recaudado empieza en cero y es de solo lectura en esta API. Los aportes corresponden a otra funcionalidad.

## Migración

`0003_campania_creador_alter_campania_imagenes` incorpora el dueño y permite omitir la imagen.
Las campañas anteriores se conservan sin dueño; no se asignan automáticamente ni aparecen en Mis campañas hasta que se les asigne uno.
Las imágenes locales se guardan en `media/`, excluido de Git.

## Comprobación en Windows (PowerShell, desde la raíz)

```powershell
$env:DB_NAME = "crowdstarter"
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe -m pytest api/test_registro.py api/test_login.py api/test_campanias.py --ds=config.settings -v
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
```

Para el navegador, mantener Django en el puerto 8000 y Vite en el 5173. Desde `frontend`:

```powershell
npx.cmd playwright test tests/registro.spec.js tests/login.spec.js tests/campanias.spec.js --project=edge --workers=1 --reporter=list
```

Se agregan tres pruebas E2E: creación/publicación/edición con vista pública, rechazo de campos inválidos y separación de campañas por usuario. Cada ejecución crea datos de prueba en la base local utilizada por el servidor.
